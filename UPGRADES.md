# Upgrades

## 0.7.0 — signal-energy-nexus 0.7.0: SpendBy carries hours before the window resets

Pins signal-energy-nexus 0.7.0 (`3155eb0`): `Target.SpendBy` is `{ Hours Percent }` in place of `{ Instant Percent }`, the hours before the window resets that the target falls, recurring with every reset. This contract's own types are unchanged, and the bytes of a `Set.Target` and a `Set.WindowTarget` keep their size; only the meaning of a `SpendBy` moves (its datom text now reads `SpendBy.{ 48 80 }`). The digest moves by the one comment on `Target.ProviderTarget` in `ethos/signal.ethos`, `-7872982838352770340` to `-6093066433882140382`, so a 0.6.0 peer is refused at its greeting rather than misreading a target. `tests/fixtures/` holds the lines that carry a `SpendBy` and the contract identity as 0.7.0 writes them.

**A target names its window; a refusal is typed.** Pins signal-energy-nexus `9019c8c`, whose `ProviderTarget` is `{ Provider Name Target }` and in which `WindowTarget` is folded. `Set` has one target variant, `Target.ProviderTarget`, and loses `WindowTarget`: `Configure.Target.{ Claude Week SpendBy.{ 24 92 } }` sets one provider's target on one window, and a window with no target is paced `Even`. A `Set.WindowTarget` of 0.6.0 is `Set.Target` with the same three fields; the `Set` archive keeps its size. `Output.ConfigureRefused` carries the new enum `ConfigureRefused.[ TargetExceedsWindow.ProviderTarget Reason.String ]`: `TargetExceedsWindow` returns the target as it was set, refused because its hours exceed its own window's duration, and `Reason` is the string refusal of 0.6.0, unchanged. Datom text `ConfigureRefused.TargetExceedsWindow.{ Claude Session SpendBy.{ 24 92 } }` and `ConfigureRefused.Reason.«the program is not installed»`. The authored `signal.ethos` changes, so the digest moves with it, now `6564084789122138051`; the one-comment move of this entry is no longer what carries it. `tests/fixtures/` holds the lines that carry a `Target`, a `ProviderTarget`, a `Set` variant after it, a refusal and the contract identity.

## 0.6.0 — generated from Ethos by ethos-zero 28.0.0; signal-energy-nexus 0.6.0

Every type of its own is generated by ethos-zero 28.0.0 (`970459d`), a build dependency, from `ethos/signal.ethos` into `src/generated/signal.rs`; `build.rs` regenerates it at every build and refuses a committed file that differs. The `wire!` declarations are gone. Pins signal-energy-nexus 0.6.0 (`5c1ff2f`), which reorders its own outputs (`Redeemed` before `Changed`) and names `Refused`; none of those types is this contract's. The contract's identity is still the digest of `ethos/signal.ethos`.

The Ethos imports `Caller`, `ProviderTarget` and `WindowTarget` from signal-energy-nexus (`Set.Target.ProviderTarget`, `Set.WindowTarget`), where 0.5.0 declared its own `ProviderTarget` and `WindowTarget` and wrote `Target.{ Provider Target }` in place: one type each, shaped as before. They are re-exported here as the other ordinary types are.

The value wire does not move. `tests/hand_and_generated.rs` freezes the 0.5.0 hand declarations (and the ordinary ones they carry) and archives a value of every type and every variant through both: the bytes are one, each reads back as the other, and the datom texts are one. `tests/wire_fixtures.rs` still holds every value against the 0.4.0 bytes and texts.

The greeting moves once: ethos-zero 28 refuses the 0.5.0 text (`Duplicate.Input`), so the digest is now `192963525083358617` (was `-4620172360499517031`) and a 0.5.0 peer is refused at its greeting. `tests/fixtures/contract.txt` holds the new identity.

Rust names: `Query` is `Input`, `Response` is `Output`, `ProgramPath` is `Program_Data`; the caller's fields are signal-energy-nexus's `ProcessId` and `UserId`.

**The schedule's settings** (meta-signal-energy-nexus `schedule-pace`, d2be0db and dd6ec2b, carried onto the generated contract). `Set` gains `Span`, `RemoveSpan.Span`, `Override`, `RemoveOverride.Override`, `Baseline` and `TimeZone`, each configured one at a time: `Configure.Baseline.20`, `Configure.Span.{ [ Monday Tuesday Wednesday Thursday Friday Saturday Sunday ] 8 22 100 }`, `Configure.Override.{ 1794859200 1794866400 0 }`, `Configure.TimeZone.«America/Mexico_City»` (the system's zone stands until one is set). Each type is signal-energy-nexus's Library type (now at `8c861ec`), and `Target.SpendBy` carries an instant and a percent. Every `Set` archive grows to the size of `Span`, so every line holding a `Set` or a `Target` in `tests/fixtures/` is 0.6.0's; `tests/hand_and_generated.rs` proves only the types 0.6.0 leaves unchanged.

Branch-only preparation for the Flow 0.54.7 rollout; deployed with it, in the same Home generation, with signal-energy-nexus 0.5.0 and energy-nexus 0.3.2.

Repins signal 10.3.0 to 11.0.0 (`6d4eb74`), datom-codec to `09a0526`, protos to `c93b598` and signal-energy-nexus to 0.5.0 (`7ca10eb`), which carries signal-flow 61.0.0 (`4871bb8`, the contract Flow 0.54.7 is built with). `signal` declares `links = "signal"`, so a consumer carries one signal.

This crate's own types, its authored `signal.ethos` and its wire form are unchanged, and so is its contract digest; the Rust types of the recipient it reaches through signal-energy-nexus change (`Address.topic` is the `Topic` newtype). No Ethos output is generated from `signal.ethos` in this repository (it is included as text and checked by a test); nothing to regenerate.

`tests/wire_fixtures.rs` holds the wire against `tests/fixtures/`, made by 9f37cb7 (0.4.0): the rkyv bytes and the datom text of a value of every wire type and every variant, the contract digest, and the greeting and receipt that carry it. They are identical under 0.5.0. The test builds a recipient's `Address`, so signal-flow (`4871bb8`, the revision signal-energy-nexus carries) is a dev-dependency.

## 0.4.0 — no polling interval; signal-energy-nexus 0.4.0

`Set.Polling` is removed: the Energy Nexus reads a provider when a turn ends on it, when a window resets and when a reading is asked for while older than the last turn end, never on an interval, so no setting names one. `Configure.Polling.5` no longer reads, and a `Set` archive no longer carries the variant (every later variant's discriminant moves down by one; the contract digest changes with the authored `signal.ethos`). Pins signal-energy-nexus 0.4.0, which repins signal-flow 57.0.0 at `3d0a4cd`.
